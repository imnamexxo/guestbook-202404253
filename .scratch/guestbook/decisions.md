## 필수 요구사항 (시험 원문 기준)

1. 회원가입·로그인 없이 누구나 작성자 이름, 메시지, 글 비밀번호를 입력해 글을 작성한다.
2. 누구나 글 목록 전체를 볼 수 있고, 각 글에 작성자 이름, 메시지, 작성 시각이 표시된다.
3. 글 목록은 최신 작성순으로 정렬한다.
4. 글 비밀번호가 일치하면 그 글의 메시지를 수정할 수 있다.
5. 글 비밀번호가 일치하면 그 글을 삭제할 수 있다.
6. 수정과 삭제 모두 비밀번호가 틀리면 작업을 거부하고 사용자에게 명확히 안내한다. 기존 데이터는 바뀌지 않는다.
7. UI에 개발자 정보(유소영, 202404253)를 표시한다.
8. Next.js App Router + TypeScript, Neon Postgres, Vercel을 사용한다.
9. GitHub 저장소, Vercel 프로젝트, Neon 프로젝트 이름은 모두 `guestbook-202404253`이다.
10. GitHub 저장소는 Public이다.
11. 최종 제출물은 GitHub 저장소 URL과 실제로 동작하는 Vercel 배포 URL 두 개다.

## 결정사항

### 도메인
- 같은 작성자 이름으로 여러 글을 쓸 수 있다.
- 수정은 메시지만 바꾼다. 작성자 이름과 작성 시각은 유지한다.

### 글 비밀번호
- Node 내장 `crypto.scrypt`로 해시한다. 글마다 무작위 salt를 만들고 해시와 salt를 저장한다.
- 검증은 서버에서만 한다. 해시 비교에는 `crypto.timingSafeEqual`을 쓴다.
- 비밀번호, 해시, salt는 글 목록 조회 결과나 브라우저로 절대 보내지 않는다.
- 이 코드는 Node.js 런타임에서 실행한다(Edge 아님).

### 작성 시각
- DB에는 `timestamptz`로 저장한다.
- 화면에는 `Asia/Seoul` 기준 `YYYY-MM-DD HH:mm` 형식으로 표시한다. 서버가 UTC여도 어긋나지 않게 한다.

### 입력 검증
- 작성자 이름: 앞뒤 공백을 제거한 뒤 1~20자.
- 메시지: 앞뒤 공백을 제거한 뒤 1~500자.
- 글 비밀번호: 입력값을 그대로 쓴다(trim 하지 않음). 4~20자이며 공백만으로 된 값은 거부한다.
- 작성, 수정, 삭제 모두 서버에서 검증하고, 화면에 이해하기 쉬운 오류를 표시한다. 클라이언트의 `required`/`maxLength`는 보조 수단이다.

### 구현 방식
- 글 목록은 Server Component에서 조회한다. 방문하거나 새로고침하면 항상 DB의 최신 목록이 보이게 한다(정적 캐시 금지).
- 작성, 수정, 삭제는 모두 Server Action에서 처리하고, 성공하면 목록을 갱신한다.
- `DATABASE_URL`은 서버 환경변수로만 쓴다. SQL은 모두 매개변수화한다.
- 구현 전에 설치된 Next.js 16.3.7의 문서(`node_modules/next/dist/docs/`)를 확인한다.

### 화면과 안내
- 글마다 [수정]/[삭제] 버튼이 있고, 누르면 그 글 아래에 인라인 폼이 열린다.
  - 수정 폼: 기존 메시지가 채워진 입력칸, 비밀번호 칸, [저장]/[취소]
  - 삭제 폼: 비밀번호 칸, [삭제]/[취소]. 비밀번호 입력이 곧 확인 절차이므로 `confirm()`은 쓰지 않는다.
- 안내 문구는 해당 폼 바로 아래에 표시하고, 오류가 나도 입력한 메시지는 지우지 않는다.
  - 비밀번호 불일치: "비밀번호가 일치하지 않습니다. 글은 변경되지 않았습니다."
  - 없는 글(이미 삭제됨): "이미 삭제되었거나 존재하지 않는 글입니다."
  - 검증 오류: 칸별 문구(예: "이름은 1~20자로 입력해 주세요.")
  - 성공: 폼이 닫히고 글 목록이 갱신된다.
- 수정 여부는 화면에 표시하지 않고, 수정 시각 컬럼도 두지 않는다.
- 수정해도 작성 시각과 목록에서의 위치는 바뀌지 않는다.
- 정렬은 `created_at DESC, id DESC`로 한다. 페이지네이션 없이 전체 글을 표시한다.

### DB
- 스키마는 `db/schema.sql`에 둔다. `CREATE TABLE IF NOT EXISTS`만 쓰고, DROP·TRUNCATE·DELETE 등 기존 데이터를 지우거나 초기화하는 문장은 넣지 않는다.
- `npm run db:init` 스크립트가 `.env.local`의 `DATABASE_URL`로 이 스키마를 실행한다. 여러 번 실행해도 안전하다.
- `.env.local`의 `DATABASE_URL`은 Neon 프로젝트 `guestbook-202404253`의 값이다(사용자 확인). 실제 연결 성공 여부는 구현 단계에서 검증한다.
