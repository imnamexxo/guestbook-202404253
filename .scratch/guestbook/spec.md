## Problem Statement

방문자는 계정을 만들지 않고도 방명록에 글을 남기고, 다른 사람들의 글을 최신순으로 보고 싶다. 자기가 쓴 글의 메시지를 고치거나 글을 지우고 싶을 때도 로그인 없이 할 수 있어야 한다. 대신 다른 사람이 그 글을 함부로 바꾸거나 지워서는 안 된다.

시험 제출 관점에서는 이 기능이 실제 Vercel 배포 URL에서 Neon Postgres와 연결되어 동작해야 한다. 또한 Public GitHub 저장소와 함께 제출할 수 있어야 한다.

## Solution

한 페이지짜리 방명록을 만든다.

- 페이지 위쪽에는 개발자 정보(유소영 / 202404253)와 글 작성 폼(작성자 이름, 메시지, 글 비밀번호)이 있다.
- 그 아래 글 목록에 모든 글이 최신 작성 시각 순으로 나온다.
- 각 글에는 [수정]과 [삭제] 버튼이 있다. 누르면 그 글 아래에 인라인 폼이 열리고, 글 비밀번호가 일치할 때만 메시지 수정이나 글 삭제가 이뤄진다.
- 비밀번호가 틀리면 작업이 거부되고, 폼 아래에 명확한 안내가 나오며, 데이터는 그대로 남는다.
- 모든 데이터는 Neon Postgres에 저장되므로 새로고침하거나 다시 방문해도 최신 상태가 보인다.

## User Stories

### 글 작성
1. 방문자로서, 회원가입이나 로그인 없이 작성자 이름·메시지·글 비밀번호만 입력해 글을 쓰고 싶다. 그래야 부담 없이 흔적을 남길 수 있다.
2. 방문자로서, 이미 누군가 쓴 작성자 이름으로도 글을 쓰고 싶다. 이름은 계정이 아니기 때문이다.
3. 방문자로서, 글을 등록하면 곧바로 글 목록 맨 위에서 내 글을 보고 싶다. 그래야 등록됐는지 알 수 있다.
4. 방문자로서, 작성자 이름이나 메시지를 비우거나 공백만 넣으면 칸별 안내를 받고 싶다. 그래야 무엇을 고칠지 안다.
5. 방문자로서, 작성자 이름이 20자, 메시지가 500자를 넘으면 안내를 받고 싶다.
6. 방문자로서, 글 비밀번호가 4자 미만이거나 20자를 넘거나 공백만으로 되어 있으면 안내를 받고 싶다.
7. 방문자로서, 작성자 이름과 메시지 앞뒤의 불필요한 공백은 자동으로 정리되길 바란다.
8. 방문자로서, 글 비밀번호는 내가 입력한 그대로(앞뒤 공백 포함) 저장되길 바란다. 그래야 나중에 같은 값으로 인증할 수 있다.
9. 방문자로서, 작성에 실패해도 입력한 내용이 지워지지 않길 바란다. 그래야 다시 쓰지 않아도 된다.

### 글 목록
10. 방문자로서, 로그인 없이 모든 글을 보고 싶다.
11. 방문자로서, 각 글의 작성자 이름·메시지·작성 시각을 보고 싶다.
12. 방문자로서, 가장 최근에 쓴 글이 맨 위에 오길 바란다.
13. 방문자로서, 작성 시각을 한국 시간 `YYYY-MM-DD HH:mm` 형식으로 보고 싶다. 그래야 시간대를 헷갈리지 않는다.
14. 방문자로서, 페이지를 새로고침하거나 나중에 다시 와도 DB에 있는 최신 글 목록을 보고 싶다.
15. 방문자로서, 글이 하나도 없을 때는 빈 목록 안내를 보고 싶다.
16. 방문자로서, 줄바꿈이 있는 메시지를 쓴 그대로 보고 싶다.
17. 방문자로서, 다른 사람의 글 비밀번호는 화면이나 브라우저로 전달되는 데이터 어디에도 드러나지 않길 바란다.

### 메시지 수정
18. 글쓴이로서, [수정]을 누르면 그 글 아래에 기존 메시지가 채워진 수정 폼이 열리길 바란다.
19. 글쓴이로서, 글 비밀번호가 일치하면 메시지를 바꾸고 싶다.
20. 글쓴이로서, 메시지를 수정해도 작성자 이름과 작성 시각은 그대로이길 바란다.
21. 방문자로서, 글이 수정되어도 글 목록에서의 위치가 바뀌지 않길 바란다. 정렬 기준은 작성 시각이다.
22. 방문자로서, 글 비밀번호가 틀리면 수정이 거부되고 "비밀번호가 일치하지 않습니다. 글은 변경되지 않았습니다." 안내를 받고 싶다.
23. 글쓴이로서, 비밀번호가 틀려 수정이 거부되어도 내가 고쳐 쓴 메시지가 폼에 남아 있길 바란다.
24. 방문자로서, 수정할 메시지가 비었거나 500자를 넘으면 안내를 받고 싶다. 이때 기존 메시지는 바뀌지 않는다.
25. 방문자로서, 이미 삭제된 글을 수정하려 하면 "이미 삭제되었거나 존재하지 않는 글입니다." 안내를 받고 싶다.
26. 방문자로서, [취소]로 수정 폼을 닫고 싶다.
27. 글쓴이로서, 수정에 성공하면 폼이 닫히고 목록에서 바뀐 메시지를 보고 싶다.

### 글 삭제
28. 글쓴이로서, [삭제]를 누르면 그 글 아래에 비밀번호 칸이 있는 삭제 폼이 열리길 바란다.
29. 글쓴이로서, 글 비밀번호가 일치하면 글을 삭제하고 싶다.
30. 방문자로서, 글 비밀번호가 틀리면 삭제가 거부되고 "비밀번호가 일치하지 않습니다. 글은 변경되지 않았습니다." 안내를 받고 싶다. 이때 글은 그대로 남아야 한다.
31. 방문자로서, 이미 삭제된 글을 삭제하려 하면 "이미 삭제되었거나 존재하지 않는 글입니다." 안내를 받고 싶다.
32. 방문자로서, [취소]로 삭제 폼을 닫고 싶다.
33. 글쓴이로서, 삭제에 성공하면 목록에서 그 글이 사라지길 바란다.

## Implementation Decisions

### 스택
- Next.js 16.3.7 App Router + TypeScript, React 19, Tailwind 4, `@neondatabase/serverless`.
- 구현 전에 설치된 Next.js 문서(`node_modules/next/dist/docs/`)에서 Server Actions, 캐시와 동적 렌더링, `revalidatePath`, 런타임 설정을 확인한다. 이 버전은 기존 지식과 다를 수 있다.

### 스키마
테이블은 하나다. 생성은 `CREATE TABLE IF NOT EXISTS`로만 하며, 기존 데이터를 지우거나 초기화하는 문장(DROP, TRUNCATE, DELETE 등)은 넣지 않는다.

```sql
CREATE TABLE IF NOT EXISTS entries (
  id            BIGSERIAL PRIMARY KEY,
  name          VARCHAR(20)  NOT NULL,
  message       VARCHAR(500) NOT NULL,
  password_hash TEXT         NOT NULL,
  password_salt TEXT         NOT NULL,
  created_at    TIMESTAMPTZ  NOT NULL DEFAULT now()
);
```

- 수정 시각 컬럼은 두지 않는다.
- 스키마 파일을 저장소에 두고, npm 스크립트 `db:init`이 `.env.local`의 `DATABASE_URL`로 이를 실행한다.

### 모듈
- **글 규칙 모듈** (순수 함수이며 DB에 접근하지 않음)
  - `validateNewEntry(input)`: 작성자 이름·메시지를 trim하고, 글 비밀번호는 그대로 둔 채 검증한다. 정상이면 정리된 값을, 아니면 칸별 오류를 돌려준다.
  - `validateMessage`, `validatePassword`: 수정과 삭제에서 쓴다.
  - `hashPassword(password)`: 무작위 salt를 만들고 `crypto.scrypt`로 해시해 `{ hash, salt }`를 돌려준다.
  - `verifyPassword(password, hash, salt)`: `crypto.timingSafeEqual`로 비교해 boolean을 돌려준다.
  - `formatCreatedAt(date)`: `Asia/Seoul` 기준 `YYYY-MM-DD HH:mm` 문자열을 돌려준다.
- **글 저장소 모듈** (서버 전용)
  - `listEntries()`: `ORDER BY created_at DESC, id DESC`로 전체 글을 조회한다. 공개 필드(id, 작성자 이름, 메시지, 작성 시각)만 선택하며, 해시와 salt는 조회 결과에 포함하지 않는다.
  - `insertEntry`, `getEntryCredentials(id)`, `updateMessage(id, message)`, `deleteEntry(id)`
  - 모든 SQL은 매개변수화한다(`neon` tagged template). `DATABASE_URL`은 서버 환경변수로만 읽는다.
  - `updateMessage`는 `message` 컬럼만 바꾼다. 작성자 이름과 `created_at`은 절대 건드리지 않는다.
- **Server Actions**: `createEntry`, `editEntry`, `removeEntry`
  - `useActionState`와 함께 쓰는 형태로, `(prevState, formData) => ActionState`를 따른다.
  - `ActionState`는 `{ ok: boolean, message?: string, fieldErrors?: Record<string,string>, values?: {...} }`이며, 실패하면 입력값을 되돌려준다. 비밀번호는 되돌려주지 않는다.
  - 처리 순서: 서버 검증 → 대상 글의 해시와 salt 조회 → 없으면 "이미 삭제되었거나 존재하지 않는 글입니다." → `verifyPassword`가 false면 "비밀번호가 일치하지 않습니다. 글은 변경되지 않았습니다."를 돌려주고 DB에 쓰지 않음 → 성공하면 쓰기와 `revalidatePath('/')`
  - Node.js 런타임에서 실행한다(Edge 금지).
- **페이지** (Server Component)
  - 요청마다 DB를 조회하도록 동적 렌더링한다. 정적 캐시에 옛 목록이 남지 않아야 한다.
  - 구성: 개발자 정보 헤더, 작성 폼, 글 목록. 글이 없으면 빈 목록 안내를 보여준다.
  - 메시지는 `whitespace-pre-wrap`으로 줄바꿈을 보존한다. 출력은 React 기본 이스케이프를 따르며 HTML을 직접 삽입하지 않는다.
- **클라이언트 컴포넌트**
  - 작성 폼과 글 항목의 수정·삭제 인라인 폼이다. 열림과 닫힘 상태, 액션 결과 표시를 맡는다.
  - `required`/`maxLength`는 보조 검증이다.
  - 수정·삭제 폼은 글 id를 hidden 필드로 보낸다. 서버는 이 id를 정수로 검증한다.

## Testing Decisions

- **좋은 테스트의 기준:** 모듈의 공개 동작만 검증하고 내부 구현은 검증하지 않는다. 예를 들어 "틀린 비밀번호는 false", "공백만 있는 이름은 오류"처럼 확인한다.
- **자동 테스트 대상 (1개 seam):** 글 규칙 모듈이다. Node 25 내장 `node:test`로 TS 파일을 직접 실행하며, 추가 의존성은 없다. npm 스크립트 이름은 `test`다.
  - 검증 경계값: 이름 0/1/20/21자, 메시지 0/1/500/501자, 비밀번호 3/4/20/21자, 공백만 있는 값, trim 동작, 비밀번호는 trim하지 않음
  - 비밀번호: 같은 비밀번호도 salt가 달라 해시가 다름, 올바른 비밀번호는 true, 틀린 비밀번호는 false
  - 작성 시각: UTC `2026-09-30T05:05:00Z`가 `2026-09-30 14:05`로 표시됨
- **DB·Server Action·UI:** 운영 DB 데이터를 보존해야 하므로 자동 테스트를 하지 않고, 아래 수동 인수 검증으로 확인한다.
- **기존 사례(prior art):** 저장소에 기존 테스트가 없다. 이번이 첫 테스트다.
