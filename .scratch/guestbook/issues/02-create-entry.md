# 02: 글 작성과 입력 검증, 글 비밀번호 해시 저장

**What to build:** 방문자가 로그인 없이 작성자 이름·메시지·글 비밀번호를 입력해 글을 등록하면 글 목록 맨 위에 나타난다. 잘못된 입력은 칸별로 안내하고, 입력한 값은 폼에 남긴다. 글 비밀번호는 글마다 salt를 둔 scrypt 해시로만 저장한다.

**Blocked by:** 01

**Status:** done

**포함 요구사항:** R1, R1-a, R2(비밀번호·해시·salt 비노출)

## 작업 범위
- 글 규칙 모듈을 만든다.
  - `validateNewEntry`, `validateMessage`, `validatePassword`
    - 이름과 메시지는 trim한 뒤 검증한다.
    - 비밀번호는 trim하지 않되, 공백만으로 된 값은 거부한다.
    - 길이는 이름 1~20, 메시지 1~500, 비밀번호 4~20자다.
  - `hashPassword`, `verifyPassword`: `crypto.scrypt`와 무작위 salt를 쓰고, `timingSafeEqual`로 비교한다.
- 글 저장소 모듈에 `insertEntry`를 만든다(매개변수화 SQL).
- `createEntry` Server Action을 만든다.
  - Node.js 런타임에서 서버 검증 → 해시 → 저장 → 목록 갱신 순으로 처리한다.
  - 실패하면 칸별 오류와 입력값을 돌려준다. 비밀번호는 돌려주지 않는다.
- 작성 폼 클라이언트 컴포넌트를 만든다. `useActionState`를 쓰고, 성공하면 폼을 비우며, `required`/`maxLength`를 보조로 둔다.
- 구현 전에 설치된 Next 문서에서 Server Actions와 `useActionState`, `revalidatePath`를 확인한다.

## 검증 방법
- 브라우저에서 작성과 검증 오류를 확인한다. 서버 검증은 개발자 도구에서 `maxLength`를 지우거나 이와 같은 방법으로 우회해 확인한다.
- DB 저장값은 SQL 콘솔에서 `[검증]` 글만 조회해 확인한다. 기존 글은 수정하거나 지우지 않는다.
- 수행하지 않은 검증은 **미수행**으로 기록한다.
