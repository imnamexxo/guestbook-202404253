# 03: 메시지 수정과 글 삭제, 비밀번호 불일치 거부와 안내

**What to build:** 방문자가 글의 [수정]이나 [삭제]를 누르면 그 글 아래에 인라인 폼이 열린다. 글 비밀번호가 일치할 때만 메시지가 바뀌거나 글이 지워진다. 비밀번호가 틀리거나 이미 삭제된 글이면 작업을 거부하고, 폼 아래에 명확한 안내를 보여주며, 데이터는 그대로 둔다.

**Blocked by:** 02 (글 규칙 모듈의 검증·비밀번호 함수와 작성 흐름이 필요함)

**Status:** done (브라우저 UI 조작 확인은 미수행)

**포함 요구사항:** R4, R4-x, R5, R5-x, R6

## 작업 범위
- 글 저장소 모듈에 `getEntryCredentials(id)`, `updateMessage(id, message)`, `deleteEntry(id)`를 만든다. `updateMessage`는 message 컬럼만 바꾼다.
- `editEntry`와 `removeEntry` Server Action을 만든다. 처리 순서는 다음과 같다.
  1. id(정수)와 입력을 검증한다.
  2. 대상 글의 해시를 조회한다. 글이 없으면 "이미 삭제되었거나 존재하지 않는 글입니다."를 돌려준다.
  3. `verifyPassword`가 false면 "비밀번호가 일치하지 않습니다. 글은 변경되지 않았습니다."를 돌려주고 DB에 쓰지 않는다.
  4. 성공하면 쓰기와 목록 갱신을 한다.
- 글 항목 클라이언트 컴포넌트를 만든다.
  - [수정] 폼: 기존 메시지 채움, 비밀번호, [저장]/[취소]
  - [삭제] 폼: 비밀번호, [삭제]/[취소]. `confirm()`은 쓰지 않는다.
  - 오류가 나면 입력한 메시지를 유지하고, 성공하면 폼을 닫는다.

## 완료 기준
- [x] 올바른 비밀번호로 `[검증]` 글을 수정하면 메시지만 바뀐다. 작성자 이름·작성 시각·목록 위치는 그대로다(새로고침 후에도).
- [x] 틀린 비밀번호로 수정하면 불일치 안내가 폼 아래에 보이고, 새로고침해도 메시지가 수정 전 그대로다. 고쳐 쓴 메시지는 폼에 남는다.
- [x] 수정 메시지가 비었거나 501자면 칸 오류가 나고 기존 메시지는 바뀌지 않는다.
- [x] 올바른 비밀번호로 `[검증]` 글을 삭제하면 목록에서 사라지고, 새로고침해도 없다.
- [x] 틀린 비밀번호로 삭제하면 불일치 안내가 보이고, 새로고침해도 글이 남아 있다.
- [ ] 두 탭에서 같은 `[검증]` 글을 연 뒤 한쪽에서 삭제하고 다른 쪽에서 수정·삭제하면 "이미 삭제되었거나 존재하지 않는 글입니다."가 보인다.
- [ ] [취소]를 누르면 폼이 닫히고 아무것도 바뀌지 않는다.
- [x] `npm test`와 `npm run build`가 성공한다.

## 검증 방법
- 로컬 `npm run dev`에서 이 티켓을 위해 새로 만든 `[검증]` 글만 대상으로 한다. 기존 글에는 수정·삭제를 시도하지 않는다.
- 데이터가 그대로인지는 새로고침한 화면과 SQL 콘솔의 `[검증]` 글 조회로 확인한다.
- 수행하지 않은 검증은 **미수행**으로 기록한다.
