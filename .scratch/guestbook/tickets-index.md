## Node 버전과 테스트 실행 방식 (확인 결과, 2026-09-30)
- **로컬:** Node v25.8.0
- **Next.js 16.3.7:** 최소 Node 20.9 (`node_modules/next/dist/docs/01-app/01-getting-started/01-installation.md`)
- **Vercel:** 새 프로젝트 기본값은 Node 24.x이고 22.x도 지원한다. Node 20은 2026-10-01에 지원이 끝난다.
- **결정:** `package.json`에 `engines.node: "24.x"`를 넣어 Vercel 빌드를 Node 24로 고정한다. 로컬 25에서도 개발과 테스트에 문제없다.
- **테스트:** `npm test`는 `node --test`로 글 규칙 모듈의 `.ts` 테스트를 바로 실행한다.
  - Node 22.18+ / 24+에서 기본 지원하는 타입 제거(type stripping)만 쓰므로 Node 25 전용 기능에 기대지 않는다.
  - 그래서 테스트 대상 코드는 지울 수 있는 TS 문법만 쓴다. enum, namespace, 생성자 매개변수 속성은 쓰지 않는다.
  - 테스트는 로컬에서만 돌리고 Vercel 빌드에는 넣지 않는다.
- **DB 초기화:** `npm run db:init`은 Node 20.6+의 `--env-file=.env.local`로 환경변수를 읽는다.

## 검증 원칙
- DB·Server Action·UI는 수동 인수 검증으로 확인하고, 각 티켓에서 새로 만든 `[검증]` 글만 사용한다. 기존 글은 읽기만 한다.
- 각 티켓의 "검증 기록" 표에 통과/실패/미수행을 근거와 함께 적는다. 수행하지 않은 검증은 통과로 쓰지 않는다.
